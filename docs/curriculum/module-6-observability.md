# Module 6: observability

Intermediate to advanced. The player learns to find evidence before changing anything: events on the right object, current and previous logs, per-container metrics, exit codes and termination reasons, live inspection with ephemeral debug containers, and checking a monitoring contract against a real scraper. Add-on: `metrics-server` (levels 1 and 3, declared in `requires`). Images are stock: python:3.12-alpine scripts in ConfigMaps, busybox, nginx alpine, hashicorp/http-echo (a shell-less binary, used for the debug container level), curlimages/curl.

Overlap decisions (follow the README ownership table): level 5 is only about choosing a probe type; level 6 is only about telling OOMKilled, an app exit and a liveness kill apart; level 8 is timeouts under load; level 11 the readiness path; level 12 failureThreshold math; level 13 startupProbe. Resource sizing stays in modules 1, 9 and 11. The module has no beginner levels; a first-contact tool (events, logs) is still taught at the start but with a believable twist. Slug order is fixed, so levels 11-15 keep a similar difficulty band to 8-10 while using different mechanisms.

Rule for this module: no level may be solved by changing a value that only the validator reads. In every level the evidence is produced by real behaviour (a process that exits, a kubelet event, a scraper that scrapes).

## Notes

- Add-ons: `metrics-server` for levels 1 and 3 only. Level 3 checks the effect via cgroup `cpu.max` (works on cgroup v2 kind nodes; fall back to `cpu.cfs_quota_us`) because `kubectl top` lags by a minute.
- Level 1 is reinterpreted: the slug is about the metrics pipeline; we cannot deploy a broken second metrics-server without touching the add-on, so the broken component is a client using the wrong Metrics API version.
- Level 7 is reinterpreted: real MemoryPressure on a kind node would risk the node itself. The scenario uses kubelet evictions for an emptyDir size limit, with node conditions healthy as the lesson. To verify on the cluster: eviction latency (about 10-60s) for `settle_seconds`.
- Level 9 needs the debug container to run as root to read `/proc/1`; verify `hashicorp/http-echo`'s user and that `kubectl debug --target` works with it. gRPC probes (level 5) need a gRPC server, which stock images lack; they are covered in the debrief only.
- Levels 8, 12, 13 share a probe-test server (python, stdlib) but have different ConfigMap scripts; write each separately (check_duplicates).
- Level 6 uses LimitRange in `cart`; it is created from `broken.yaml` and removed with the level.
- Level 10 needs a second namespace `cache-tier`, created in `broken.yaml`.
- Everything uses stock images; no custom builds.
