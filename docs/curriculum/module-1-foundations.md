# Module 1: foundations

First contact with a broken cluster. The player learns the investigation loop (`get`, `describe`, `logs`, `logs --previous`, `get events`, `get -o yaml`) on pods and their closest neighbours: crash and pull failures, Pending, env, ConfigMap and Secret consumption, labels and Service basics, multi-container pods, init containers, DaemonSet, Job, CronJob, LimitRange and finalizers. No add-ons. Everything is stock images: `nginx:1.27-alpine`, `busybox:1.36`, `python:3.12-alpine` (stdlib scripts in ConfigMaps), `hashicorp/http-echo`, `curlimages/curl`.

Overlap decisions: OOMKilled belongs here only as "recognise it and size the limit" (l13); m6 l6 and m11 l12 own the harder angles. Service wiring is split by field: l7 is label/selector mismatch fixed on the Deployment side, l8 is Service `port` vs `targetPort`; m3 owns everything deeper (named ports, EndpointSlices, multi-port). Scale, HPA, PDB, probes and rollouts are module 2 and are not used as fixes here. Taints and affinity are only touched by l15 (nodeSelector) and l16 (DaemonSet toleration); m9 owns the rest. Every validator proves behaviour from a `curlimages/curl` probe pod or from pod state over a short window, and every level keeps its workload object so deleting it cannot pass.

## Notes

- Shared fixtures: a `probe` pod (`curlimages/curl:8.10.1` with `sleep 3600`) created by each validator or setup; curl `--max-time 5`. Images pinned: `nginx:1.27-alpine`, `busybox:1.36`, `python:3.12-alpine`, `hashicorp/http-echo:1.0`.
- No add-ons required. Nothing here touches pre-existing cluster objects.
- l6 needs a second namespace `orders-staging`, created by `broken.yaml` (so it is deleted between levels). l15 labels two workers in `setup.sh` with `disk=ssd` / `disk=hdd`; node reset removes them.
- l12: `ledger-db` is a busybox `nc -lk -p 5432` listener; `ledger-web` is a stdlib python server that opens a TCP connection per request.
- l17 and l18 depend on timing (shards of about 12s; cron every minute). The validators wait with bounded `kubectl wait --timeout`, l18 up to about 70s, which is the only validator slightly above the usual 60s.
- l16 is the only level whose fix is a toleration, l15 the only nodeSelector one; m9 owns the deeper treatment.
- Slugs reinterpreted: `first-pod` (the pod "exits immediately" because of a command override rather than a typo), `daemonset` (symptom is a missing pod, original text said Pending), `job-completion` (DeadlineExceeded instead of BackoffLimitExceeded, to avoid duplicating the l2 crash story), `configmap-basics` (stale env after a ConfigMap update instead of a missing ConfigMap, because missing keys and objects belong to m4/m1 l10), `limitrange` (ratio rejection instead of an injected default, so it does not end like `oomkilled`). `crashloop` uses a shared-network-namespace port clash for its own mechanism.
