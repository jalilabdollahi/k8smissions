# Module 10: operators

Expert module about extending the API server: CRD schemas and versions, controllers, and admission webhooks. Nothing is simulated: every controller is a small reconcile loop (stdlib Python in a ConfigMap, run by `python:3.12-alpine` with the pod's ServiceAccount token) and every webhook is a real HTTPS server the API server calls. Validators prove behaviour by creating probe custom resources and probe pods and watching what the controller or webhook does with them. No add-ons. Overlap decisions: module 5 owns general RBAC and module 10 l8 owns controller RBAC (including `/status`); module 1 owns generic stuck finalizers, so l4 is about the controller's delete ordering; module 7 owns stuck namespaces; module 3 and 6 own probes and DNS, so no level here is about those. Webhook scope: every webhook configuration is limited by a `namespaceSelector` on the label `k8smissions/lab=true` (set on the level's own namespaces) so a broken webhook can never touch `kube-system`, kube-proxy or CoreDNS; the "kube-system" story in l11 is played in a lab namespace `labeler-system`.

## Notes

### Controller fixture

- Image: `python:3.12-alpine`, command `["python","-u","/app/controller.py"]`, script mounted from a ConfigMap. Stdlib only. Verify the tag with `docker manifest inspect`.
- Why not kubectl: `registry.k8s.io/kubectl` is a distroless image with no shell; confirm with `docker run --rm --entrypoint sh registry.k8s.io/kubectl:v1.36.0` before relying on it. Default plan is Python.
- Shared helper (copy into each level's script, about 25 lines): read `/var/run/secrets/kubernetes.io/serviceaccount/{token,ca.crt,namespace}`, build an `ssl.create_default_context(cafile=ca)`, a function `api(method, path, body=None, content_type=...)` over `urllib.request` against `https://kubernetes.default.svc`, JSON in and out, returning `(status, obj)` without raising on 4xx so the loop can log and carry on. List-then-poll every 2 seconds (no watch) keeps scripts short and deterministic. Merge-patch with `application/merge-patch+json`, status via `/status`. Log one line per action (`reconciled <ns>/<name> gen=<n>`) so players can read behaviour from `kubectl logs`.
- Each level's script is different in logic (the bug is in the logic), so duplicate-detection should not fire. Keep the helper under about 25 lines, since it is the only shared part.
- Config comes from env fed by a ConfigMap (`operator-config`) in levels that teach it (l3, l12, l13). Remind authors: env from a ConfigMap is read at pod start only.
- Operators are Deployments in `$NS` with a ServiceAccount, Role or ClusterRole and binding created from `broken.yaml` (all labelled managed). CRDs, ClusterRoles, webhook configurations are cluster-scoped and cleaned by the label.
- Leader election (l12, l18): implement with a `coordination.k8s.io/v1` Lease: acquire by create or by patch when expired, renew every `leaseDuration/3`, step down on failed renew. Lease duration 10 seconds so failover tests fit the validator budget.
- Validators create probe objects (a probe CR, a probe pod) with a label so they are cleaned afterwards, and may delete the leader pod in l12.

### Webhook fixture

- Server: `python:3.12-alpine`, `http.server.ThreadingHTTPServer` wrapped with `ssl.SSLContext(PROTOCOL_TLS_SERVER)` and `load_cert_chain("/tls/tls.crt", "/tls/tls.key")`, listening on 8443. It handles `POST /validate`, `/mutate` or `/convert` (l2), reads an `AdmissionReview` (or `ConversionReview`) `v1`, answers with the same `apiVersion/kind`, `response.uid` echoed, `allowed`, `status.message`, and for mutations a base64 JSON patch. The cert is loaded once at start (so Secret swaps need a pod restart, which is intentional).
- Service `<name>` port 443 -> targetPort 8443, so the API server calls `https://<name>.k8smissions.svc:443`.
- Certificates are pre-generated fixtures, not created at runtime (python:3.12-alpine has no openssl and the player's host may differ). The maintainer generates once, with ECDSA P-256 keys, and the authors paste PEMs into each level's `broken.yaml` (Secret `stringData`) and `caBundle` (base64):
  - `ca-a`: root CA, 100 years.
  - `good`: signed by `ca-a`, SANs `DNS:*.k8smissions.svc, DNS:*.k8smissions.svc.cluster.local`, 100 years (the wildcard covers any service name in the fixed namespace `k8smissions`).
  - `expired`: same key and issuer, validity 2020-01-01 to 2021-01-01 (use `openssl ca -startdate 20200101000000Z -enddate 20210101000000Z`, or `openssl x509 -not_before/-not_after` on OpenSSL 3.4 or newer).
  - `nosan`: signed by `ca-a`, CN only, no SAN (l18).
  - `ca-b`: an unrelated root, used as the stale `caBundle` (l5).
- The PEM blocks will repeat across levels. They are fixtures, not scenario text; ask the maintainer to make `scripts/check_duplicates.py` ignore `-----BEGIN` blocks if it flags them.
- Safety: every webhook configuration has `namespaceSelector` `matchLabels: {k8smissions/lab: "true"}` and the level's namespaces carry that label; webhook scope never includes `kube-system`, so a bad server cannot take down cluster DNS or kindnet. l11 exploits this: its "system" namespace is the lab namespace `labeler-system`.
- Namespaces created by a level are deleted afterwards when `broken.yaml` creates them (authoring guide).

### Slugs reinterpreted

- `olm-subscription` (l6): OLM is not installed. Kept the theme (channel, pinned version, upgrade graph) with an operator installed from plain manifests where the pinned bundle and the upgrade path (`replaces`) are wrong, proven by the running operator's version and migrated objects.
- `webhook-cert` (l5): the literal caBundle problem is real; the second layer (expired serving cert) uses the fixture `expired`.
- `admission-webhook-selector` (l11): the original story (kube-system DNS breaks) is replaced by the same failure mode in a lab namespace, because a broken webhook in `kube-system` could break the player's cluster.
- `crd-conversion` (l2): the converter is a working service, so the player wires the CRD to it instead of writing one.
- `operator-panic` (l15): the original Go nil-pointer is a Python `TypeError` in the script, same lesson.
- `crd-storage-migration` (l17): the API server does not let you drop a stored version outright (it rejects it), so the scenario is the real recovery: rewrite the objects, then fix `storedVersions`.

### Engine requests

None for this module, other than the optional `check_duplicates.py` ignore for PEM blocks.

### First-half build notes (levels 1-9)

- Fixtures are built and documented in `modules/module-10-operators/_fixtures/README.md`. The helper ConfigMap `kapi-lib` must be mounted at `/kapi`, never `/lib` (that hides the musl loader and python fails with "no such file").
- l9: the validator runs the CronJob `sla-reporter` once with `kubectl create job --from=cronjob/sla-reporter` instead of waiting for its schedule.
- l1: the Job stops at the first rejected policy (dry run), so the two schema faults appear one after the other.
- l3: the operator's `WATCH_NAMESPACE` points at an existing empty namespace `staging`, so nothing errors.

### Second-half build notes (levels 10-18)

- Spikes on kind 1.36: mutating webhooks work (the JSON patch is applied, and `--dry-run=server` shows the mutated object, so l11 validates with it). The `nosan` cert fails with `x509: certificate is not valid for any names, but wanted to match <svc>.<ns>.svc`, not the "legacy Common Name" text (corrected in `_fixtures/README.md`, no code change). Dropping a stored version via `storedVersions` before rewriting objects fails reads with `request to convert CR from an invalid group/version` (l17 trap confirmed).
- l10: the bug is a status patch with a fresh `lastSync` and `observedGeneration = old + 1`; the validator samples `resourceVersion` for 15 s, changes the spec, then deletes a child.
- l11: `labeler-system` and `shop` are created by `setup.sh` (labelled managed and lab). The webhook is registered while the server is scaled to 0, then the server is scaled up and `storefront` restarted, so the ReplicaSets hit "no endpoints". No `broken.yaml`.
- l12: the lease name comes from the Deployment env (`LEASE_NAME` from the downward API), not from `operator-config` (l3 owns ConfigMap env); the stability window is 15 s, and liveness of a lease is judged by its `renewTime` moving between two samples.
- l13: the throttle is the `INVENTORY_DELAY` env of `asset-inventory` (Deployment env, not a ConfigMap).
- l15: the first crash is `TypeError: 'NoneType' object is not iterable` (the list of a missing CRD), the second is the planned `'NoneType' object is not subscriptable` on `legacy-sync`. `release-manifests` is created by `setup.sh`; the CRD the player applies is in mission `cleanup`. The validator creates a Workload without `spec.options`, so only a controller fix passes.
- l17: `crd-sync` is a Python Job that retries every 5 s (a stock kubectl image has no shell); the full fix is storage swap, rewrite, `storedVersions`, then the Job removes `v1alpha1`.
- l18: `orders` is created by a Job (`queue-publisher`, raw API, so pruning is silent; kubectl's strict validation would have shown the unknown field). The cert fault uses `nosan`; the RBAC fault makes the operator fail open (both replicas lead). Because `orders` was already stored without `deadLetter`, it has to be applied again after the schema fix.
