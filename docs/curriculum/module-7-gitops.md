# Module 7: gitops

Delivery as code: Helm releases (values precedence, rollback history, YAML typing), Kustomize (overlays, silent no-op transformers, leftover objects), and Argo CD core (sync failures, hooks, self-heal, drift, ignoreDifferences, secrets that must stay out of Git), plus two cluster-hygiene levels (graceful shutdown during a rollout, a namespace that cannot be deleted). Add-ons: `argocd` for the Argo levels; levels 8 and 11 also list `metrics-server` in `requires` because an HPA is part of the scenario. Overlap decisions: module 2 owns plain rollout mechanics and basic HPA, so the HPA levels here are only about what Git and Argo do to an HPA; module 1 and module 10 own finalizers, so level 15 is about a different reason a namespace stays Terminating (a dead aggregated API); module 11 owns SIGTERM-ignoring workloads, so level 6 is only the endpoint-removal race solved with a preStop sleep; module 5 owns Secrets/RBAC basics, so level 7 is only about the Git-versus-live-Secret ownership problem. Module 7 is advanced overall; slugs 11 to 15 were added after the first ten, so difficulty follows the folder numbers loosely rather than strictly.

## Notes

**Git fixture (one approach for all Argo levels, and reused by module 8).** Namespace `gitops-git` (created by each level's `setup.sh`, label `k8smissions/managed=true`; deleted between levels, so every level recreates it). One Deployment and Service `gitserver` (port 8080), image `alpine/git` pinned to a verified tag, running BusyBox `httpd -f -p 8080 -h /srv/www -c /srv/httpd.conf` with a CGI script `/srv/www/cgi-bin/git` that does `exec git http-backend` with `GIT_PROJECT_ROOT=/srv/git`, `GIT_HTTP_EXPORT_ALL=1`, and `http.receivepack=true` in the global git config. Bare repos live in an emptyDir at `/srv/git/<name>.git`. In-cluster URL: `http://gitserver.gitops-git.svc.cluster.local:8080/cgi-bin/git/<name>.git`. `httpd.conf` only protects the path prefix `/cgi-bin/git/private/` (used by module 8, not here). Seeding: each level's `setup.sh` copies its repo tree from the level directory into the pod with `kubectl exec -i ... tar x`, then runs `git init`, commits (`user.name`/`user.email` set per command), and creates the branch `main`; do it once per level, keep the snippet small and different per level to stay clear of `check_duplicates.py`. Player access: `kubectl -n gitops-git port-forward svc/gitserver 8080:8080` then `git clone http://localhost:8080/cgi-bin/git/<name>.git`, edit, commit, `git push origin main`; fallback with no local git: `kubectl exec -it -n gitops-git deploy/gitserver -- sh` (git is in the pod). Helm and Kustomize levels (1, 3, 12, 13) use the same clone for chart and overlay files. Argo CD needs no repository credentials for this unauthenticated repo. First task for the fixture owner: a short spike proving BusyBox httpd plus `git-http-backend` clones and pushes with the stock image; if it fails, fall back to `git daemon --enable=receive-pack` on port 9418 (`git://` URLs) and update this note, because everything else is written against "an HTTP or git URL in `$REPO`".

**Argo CD mechanics for authors.** Core install has no API server: Application objects live in namespace `argocd` with label `k8smissions/managed=true` (cleanup removes them; use `metadata.finalizers: [resources-finalizer.argocd.argoproj.io]` only where the level needs cascade). Destination namespace is `$NS` unless the level is about a missing namespace (levels 4, 15). The controller polls Git every 3 minutes and `argocd-cm` is an add-on object we must not edit, so setups, validators and solutions speed things up with `kubectl annotate app NAME -n argocd argocd.argoproj.io/refresh=hard --overwrite`, and request manual syncs with `kubectl patch app NAME -n argocd --type merge -p '{"operation":{"sync":{}}}'`. Set `settle_seconds` to at least 25 for Argo levels and `solve_timeout` to 120 or more. Validators must check the workload from a probe pod, not only the Application status (levels 5 and 10 are built to punish that).

**Other shared choices.** Images: `python:3.12-alpine` for apps and the schema stub (scripts in ConfigMaps), `hashicorp/http-echo` (level 6), `nginx:*-alpine`, `curlimages/curl` for probes and the request loop. Helm and Kustomize CLIs run on the player's machine and on the test host in `setup.sh`; release history for levels 1 and 2 is built by running real `helm install/upgrade` from `setup.sh` using chart files from the level directory, with `helm` objects carrying the managed label through chart templates. Levels 8 and 11 use `requires: ["argocd", "metrics-server"]`.

**Reinterpreted slugs.**
- `level-7-external-secrets`: External Secrets Operator is not installed and needs a real backend. Theme kept (secrets must not live in Git) with a real mechanism: Git versus live Secret ownership under self-heal and prune, proven by a gateway that checks the rotated password.
- `level-13-helm-values-indent`: a pure indentation error is shallow and duplicates level 1's "value silently ignored" story. Kept the "values file looks right but is read differently" theme with YAML scalar typing (`1.30` read as `1.3`).
- `level-8-autoscaler`: Cluster Autoscaler cannot run on kind. Replaced by GitOps versus HPA over `replicas`, the module scope's own item.
- `level-15-namespace-stuck`: module 1 and module 10 own stuck finalizers, so this level is the other common cause, a dead aggregated APIService. The APIService is cluster-scoped and carries the managed label so cleanup removes it.
- `level-3-kustomize-overlay`, `level-9-production-runbook`, `level-10-grand-finale`: same theme, new mechanisms (leftover prefixed objects, Argo hooks, an Argo-Helm finale with a user-side check).

**Fixture and level notes from the first-half author (levels 1 to 8).** The Git fixture is built and documented in `modules/module-7-gitops/_fixtures/gitserver/README.md`. `alpine/git` has no BusyBox `httpd`, no `git-http-backend` and no `git-daemon`, so the server is `python:3.12-alpine` running a small smart-HTTP script (`server.py`) with the `git` binary copied in by an `alpine/git:2.49.1` init container; URLs, the `/cgi-bin/git/private/` basic-auth prefix (`ci-bot` / `ci-bot-secret`) and port 8080 are exactly as specified above. Helpers for `setup.sh`: `gitserver/seed.sh`, `commit.sh`, `up.sh`; `_fixtures/argo-app.sh` creates labelled Applications; `_fixtures/probe.yaml` is the curl pod. Level changes: level 1 uses `hashicorp/http-echo` tags (0.2.3 to 1.0) instead of 1.27.2, and the chart default repository is an unpullable dev registry (the upgraded pod is ImagePullBackOff, one old pod keeps serving). Level 3's staging quota makes the `stg-` pods fail admission (FailedCreate) rather than stay Pending. Level 4 sets `managedNamespaceMetadata` labels so the namespace Argo creates is cleaned up. Level 6 has no Argo Application (plain Deployment). Level 7 gives the rotated password in Secret `ledger-db-rotated` and a `db-gateway` stub.

**Second-half notes (levels 9 to 15).** Changes from the map, all built and tested. Level 9: the stale failed Job with an immutable template is not a fault in Argo CD v3 (it replaces a failed hook by itself), so the two faults are now the migration Job annotated `PostSync` (deadlock: the new pods are not healthy until the migration ran, so the sync waits for health forever and the operation has to be terminated with `status.operationState.phase: Terminating`), then the Job's ConfigMap `migrations` that only exists in a later sync wave (`CreateContainerConfigError` once the Job is `PreSync`). Level 10 has four faults: deleted branch, misspelled values file, a namespace ResourceQuota that rejects pods without requests, and a wrong Service `targetPort` that Argo reports as Healthy. Level 12: current kustomize fails on a `replicas` entry that matches nothing, so the two silent no-ops are a JSON patch whose `target.name` matches no resource and an `images` entry with the short image name; the validator also renders the overlay from repo HEAD, so the fix must be committed. Level 13 uses `hashicorp/http-echo` tag `1.0`, which YAML reads as `1` (no such tag). Level 14: the app reads its ConfigMap through the API on every request, so the Git fix takes effect without a pod restart. Level 15: the Application owns the Namespace object, which is why it stays stuck with the namespace; the APIService and its Service in `k8smissions` carry the managed label.
