# Module 5: security

Intermediate to advanced. Players meet security as it shows up in an incident: an in-cluster client gets a 403, a hardening setting breaks an app, an admission rule rejects a rollout, a guardrail (quota, taint, PriorityClass, NetworkPolicy) does the opposite of what the owner intended. No add-ons. Everything runs on stock images (python:3.12-alpine scripts in ConfigMaps calling the API with the SA token, curlimages/curl, nginx alpine, nginxinc/nginx-unprivileged, busybox, registry.k8s.io/pause). Levels that need a second namespace (PSA, finale) create their own namespace in `broken.yaml`; nothing pre-existing is touched.

Overlap decisions: module 5 owns RBAC and the "isolation" use of NetworkPolicy, taints, node affinity and PriorityClass. Mechanics of NetworkPolicy syntax stay in module 3, scheduler mechanics (effects, preemption algorithm, topology) in module 9, drain procedure in modules 2/11/12, quota pressure under load in module 11. Here a quota is a guardrail the team set on purpose, a taint is a dedicated-pool fence, a PDB protects a quorum. Slug order is fixed, so level 10 (the finale) is not the last row: it combines levels 1-9 topics only, and levels 11-15 are advanced/expert standalone levels.

Every level ends with a different fix: Role rule on a subresource, emptyDir under a read-only root, requests/limits (or LimitRange defaults) for a quota, deleting a permissive policy, a required affinity, tolerations, a PDB selector, a new PriorityClass, a ServiceAccount binding, runAsNonRoot on two containers, stale Jobs, a minimal capability set, a label on a ClusterRole.

## Notes

- Fixtures: ConfigMap scripts in `python:3.12-alpine` (API client with SA token, stdlib only), `curlimages/curl` loops, `nginx:1.27-alpine`, `nginxinc/nginx-unprivileged`, `busybox:1.36`. Pin exact tags and check with `docker manifest inspect`.
- Level 5 and 6 use `setup.sh` to label/taint a worker (node state is reset between levels); validators look nodes up by label, never by name.
- Level 9: `setup.sh` reads node allocatable CPU and creates low-priority filler pods sized to leave less free than `checkout` needs; needs real-cluster verification that preemption fires after the fix within `solve_timeout`.
- Level 12 uses a ValidatingAdmissionPolicy (GA, built in), labelled `k8smissions/managed=true`, so it is cleaned up with the level.
- Level 14: allowed capability set should be confirmed empirically on the pinned nginx image; the validator checks a denylist plus non-privileged, not an exact list.
- Level 13 timing: terminal pods are produced by short Jobs in `setup.sh` and must be Completed before the check starts (`settle_seconds` accordingly).
- No slug is reinterpreted beyond scenario choice; `chaos-finale` is capped at levels 1-9 topics and sits at position 10 because slugs are fixed.
- Levels 9-15 as built: L9 `setup.sh` creates `batch-low`/`platform-critical` (labelled) plus a filler sized from node free CPU; the player's new class is `checkout-critical` (both names in `cleanup`). L10 RBAC fault is a Role with only `list`/`watch` (app needs `get`), the network fault is a policy admitting the wrong pod label; validated through the API-server service proxy and a `rogue` pod. L12 installs the ValidatingAdmissionPolicy in `setup.sh` (namespace-scoped binding) and waits until it denies. L13 quota is created by `setup.sh` after 8 finished Jobs exist; a `rollout restart` is needed after the fix because the ReplicaSet backs off. L14 serves a ConfigMap nginx.conf on a named port; the working set is CHOWN, SETUID, SETGID, NET_BIND_SERVICE. L15 also has a correctly labelled third contributor (`ticket-notes`). L10 xp set to 300 to match the lint rule for expert.
