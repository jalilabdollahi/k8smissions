A leak has a slope that never flattens, so a bigger limit only moves the kill later. A plateau has a stable size that is simply above the limit, so it needs room, not a cure. Check what each app reports about itself in its logs and which environment variables the Deployments set: one of the two apps has a knob that bounds its cache, the other one needs its whole data set in memory (read its log line, and what happens when the knob is lowered).
See: kubectl set env --list deployment/profile-api  and  kubectl explain pod.spec.containers.resources
