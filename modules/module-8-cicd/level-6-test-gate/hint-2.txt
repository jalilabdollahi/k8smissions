`onError: continue` on a step lets the Task go on after that step fails, and the step's exit code is then recorded in a file at `$(steps.step-<name>.exitCode.path)` (`kubectl explain task.spec.steps.onError`; note the `step-` prefix in that reference). That is useful for a report step that must always run, but then something has to turn the recorded exit code back into a failure, otherwise the Task is green by construction.
