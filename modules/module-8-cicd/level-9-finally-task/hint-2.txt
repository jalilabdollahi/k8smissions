Tasks listed under `spec.tasks` are skipped when something they depend on fails. A Pipeline has a second list, `spec.finally`, whose Tasks run at the end whatever happened (`kubectl explain pipeline.spec.finally`). Careful with what a finally Task may reference: a result of a Task that failed before it wrote that result does not exist, and a finally Task that waits for it never starts, so the run hangs. The run's own name always exists, as `$(context.pipelineRun.name)`.
