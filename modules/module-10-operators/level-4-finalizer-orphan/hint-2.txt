A finalizer holds a deleted object in the API (with `metadata.deletionTimestamp` set) until its controller has finished its cleanup and removes the entry. Read the delete branch in the operator's code (`kubectl -n k8smissions get cm datastore-operator-code -o yaml`) and ask in which order it does the two things, and what it still has access to by the time the second one runs. Fixing the code does not remove what has already leaked.
