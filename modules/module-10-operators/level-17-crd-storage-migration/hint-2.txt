`status.storedVersions` records every version the objects in etcd may have been written with. The API server refuses to drop a version from `spec.versions` while it is listed there, and it only lets you remove it from the list once nothing is stored in that version, which you have to ensure yourself. Objects are re-stored in the current storage version whenever they are written. Order matters: first the storage version, then the objects, then `storedVersions` (it is a status field: `kubectl patch ... --subresource=status`). Patching the list first makes the error go away and breaks reading the objects.
