There are two separate causes. The first crash is because the API the operator lists does not exist: the release was installed without its CRD, which is kept in ConfigMap `release-manifests` together with the three Workloads (CRD first, then the resources). Once the CRD exists the pod may crash again, with a different message: read `--previous` logs again and look at which Workload the code was handling. The controller code is in ConfigMap `workload-operator-code`. After a crash loop, a restart is quicker than waiting for the back-off.
