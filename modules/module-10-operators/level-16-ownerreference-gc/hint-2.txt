The garbage collector deletes an object when every owner named in its `ownerReferences` is gone, and it identifies an owner by `uid`, not by name: a live owner with a different uid counts as gone. An object with no `ownerReferences` is never collected. The uid of a custom resource is assigned by the API server at creation and changes when you recreate it, so it cannot be a constant in the controller's code (ConfigMap `site-operator-code`). See `kubectl explain deployment.metadata.ownerReferences`.
