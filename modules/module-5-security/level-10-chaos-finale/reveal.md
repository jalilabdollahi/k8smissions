**Fix, in the order the symptoms appear**

1. `kubectl -n settle describe rs -l app=settlement` shows `violates PodSecurity "restricted:latest"`. Patch the Deployment: pod `securityContext` gets `runAsNonRoot: true` and `seccompProfile: {type: RuntimeDefault}` (it already has `runAsUser: 1000`), the container gets `allowPrivilegeEscalation: false` and `capabilities.drop: ["ALL"]`.
2. The ReplicaSet now reports `failed quota: settle-quota: must specify limits.cpu,limits.memory`. `kubectl -n settle set resources deploy/settlement --limits=cpu=200m,memory=128Mi` (the quota allows 2 CPU / 2Gi in total, so keep it modest).
3. Pods start and crash: `kubectl -n settle logs deploy/settlement` shows `cannot get resource "configmaps"`. Role `settle-config-reader` allows only `list` and `watch`: add `get` (keep `resourceNames: ["settle-config"]`), then `kubectl -n settle rollout restart deploy/settlement`.
4. The pods run but are not Ready: `/ready` says the database is unreachable. NetworkPolicy `db-clients` admits only pods labelled `app=settlement-api`; the app is `app=settlement`. Change that selector (or add a policy that allows `app=settlement` on port 5432). Do not delete the policy: `rogue` must stay locked out.
