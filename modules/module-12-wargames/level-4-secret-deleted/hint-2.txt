The database was never rotated, so its password has not changed: the two pods that are still running received it in their environment when they started (`kubectl exec <running pod> -- printenv`). A new Secret with a made-up value would let pods start and still fail every write. Remember that each consumer names the key it wants (`kubectl explain pod.spec.containers.env.valueFrom.secretKeyRef`), and the consumers do not all use the same key.
