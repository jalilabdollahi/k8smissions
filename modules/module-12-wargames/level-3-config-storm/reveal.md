1. **Bad values in `shop-config`** (`MAX_CONN` empty, `PRICING_URL` missing the colon after `http`): `shop-web` validates them at start and exits. The last good values are in `shop-config-v41` (not v38: those are older).
2. **The ConfigMap is `immutable: true`**, so `kubectl patch`/`edit` is refused. Deleting and recreating it under the same name is unreliable: the kubelet keeps an immutable ConfigMap cached while pods that reference it are still on the node, so replacement pods can start with the old content. Roll forward with a new name instead (`shop-config-v43` with the v41 values).
3. **Three consumers, three mechanisms.** `shop-web` and the `shop-report` CronJob use `envFrom`; `shop-worker` mounts the keys with `subPath`, which is never refreshed in a running container and does not crash, so it is easy to forget. Point all three at the new ConfigMap; changing the pod template restarts the Deployments (and clears the crash-loop backoff).
