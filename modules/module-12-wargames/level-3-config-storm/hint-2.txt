Try to patch the bad ConfigMap and read the error: `kubectl explain configmap.immutable` explains why it refuses. Deleting and recreating the same name is a trap here: the kubelet keeps an immutable object cached while pods that use it still run on the node, so replacement pods can start with the old content. Think like the pipeline that kept v38 and v41: a new name, then point every consumer at it. List the consumers: `kubectl -n k8smissions get deploy,cronjob -o yaml | grep -B3 -A3 shop-config`, and remember a `subPath` file never refreshes in a running pod.
