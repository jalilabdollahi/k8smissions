Four things have to line up for an API call to succeed: the pod must run as an account that exists (`spec.template.spec.serviceAccountName`), the pod must actually get that account's token (`kubectl explain serviceaccount.automountServiceAccountToken`), a RoleBinding must name that account as a subject, and permissions are per namespace, so the settings namespace needs its own RoleBinding. Test each one without running the app: `kubectl auth can-i get configmap/ledger-settings -n platform-config --as=system:serviceaccount:k8smissions:ledger-sync-v2`.
